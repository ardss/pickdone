# PickDone 同步服务 · 顶层设计与全流程规划

日期:2026-09-15 · 定位:《同步整体方案》的上位文档——回答"做哪些端、什么顺序、每条流程怎么走、后台怎么管"
流程细节的先例出处:Lemon Squeezy License API / Obsidian / SiYuan / Joplin Cloud / Bitwarden / 虎皮椒 均为官网与源码级调研(详见文末参考)

---

## 1. 顶层判断(先给结论)

1. **一个账号体系,两条收款通道,一个履约函数。** 海外 Lemon Squeezy(MoR 代缴税)、国内虎皮椒(个人可收微信/支付宝),两路 webhook 汇入同一个 `provision(user, plan)`——不做两套账号、不做两套权益。
2. **限"量"不限"设备数"。** 学 Obsidian:设备计数是让用户最痛的轴,存储才是诚实的轴。桌面设备数从宽(5 台激活位+自助解绑),配额走存储/附件。
3. **试用替代退款(国内)+ 7 天退款(海外)。** 思源的"先试用后买、订阅后不退"完美适配中国市场;海外 LS 原生支持 7 天退款。两句话术,零客服。
4. **本地数据永远不锁。** 到期/欠费/退款任何状态,只暂停同步,绝不锁本地数据——这是本地优先品牌对用户的底线承诺,也是口碑护城河。
5. **后台=薄 CRUD+支付平台面板。** 单人做不了运营中台;自建后台只做四件事:查用户、改配额、踢设备、停 license。钱的事全交给 LS/虎皮椒的面板。

## 2. 做哪些端,整体顺序

```
第一梯队(现有)     桌面 Win/Mac/Linux(同构 Electron+SFC)
第二梯队(P6)      Web PWA —— 复用 renderer SFC + 5175 shim + sync-core
第三梯队(P7)      Android —— sync-core + Capacitor 包 Web 起步
观望              iOS —— App Store 审核成本+E2E 政策,有付费基数再启
永不做            小程序(数据主权叙事冲突)、企业私有化定制(单人支持不动)
```

**顺序逻辑**:todo 用户的"第二台设备"大多是手机,但 Web 是 Android 1/5 的成本,先用 Web 验证"多端同步值得付费"再投原生。每往下一端,前一个端必须满足:付费转化 >0 且双端同步稳定运行 1 个月。

**为什么这个顺序对单人可行**:sync-core(合并/加密/传输)是平台无关 TS 模块,一处开发;每个新端只写"适配器"(存储适配+提醒适配)+复用全部 UI(Web 直接复用 SFC,Android 包之)。端越多,同步服务的边际成本越低——这就是多端与同步互为杠杆。

## 3. 全景流程图(用户视角生命周期)

```
下载安装 ──> 本地使用(无需账号,永久免费)
   │ 想多设备
   ▼
注册账号(email+密码,确认邮件激活)──> 添加设备(扫码/激活码)
   │                                          │
   │ 免费档:25MB/2设备 全功能同步(体验档)      │
   ▼                                          │
撞到墙 或 想要附件/历史/更多设备                    │
   ▼                                          │
购买(海外 LS / 国内虎皮椒)──────────────────────┘
   ▼
license 自动发放(webhook)──> 激活 ──> 配额解锁
   ▼
续费(锁首年价)/ 到期宽限14天 ──> 停止同步(数据永不锁)
   ▼
注销(自助)──> 停同步 ──> 30天硬删密文+PII
```

## 4. 账号与 ID 体系(命名空间总表)

| ID | 形态 | 产生处 | 存放 | 备注 |
|---|---|---|---|---|
| **userId** | 自增+短随机后缀(如 `u_7f3k2`) | 注册 | D1 users 表;**下发到客户端取代硬编码 840001** | 存量本地数据合并时视为"本机历史"整体并入,不改写存量 tid |
| **deviceId** | UUID | 客户端首启自生成临时 id → 激活时服务器签发正牌 | D1 devices;客户端 userData | 设备名用户可改;last_seen 心跳 |
| **fingerprint** | 机器指纹哈希(平台硬件因子) | 客户端 | 仅存哈希 | 重复激活检测;换机=旧设备自助解绑 |
| **license key** | LS 自动生成 / 国内自生成 `PD-XXXX-XXXX-XXXX` | 支付 webhook | D1 licenses | activation_limit=5;expires_at 随订阅 |
| **instance_id** | UUID | LS activate / 自建等价 | D1 + 客户端 | 一台设备一个实例,解绑即释放 |
| **数据行 id** | 存量不变;新增分类/过滤器用 `时间+随机+deviceId哈希` 64bit | 端上 | SQLite | todos 的 tid 生成器同样注入 deviceId 段(P2) |
| **tomatoId / chipId** | 现有 `tmt_`/`pl_` 时间+随机 | 端上 | SQLite | 已全局唯一,不动 |
| **oplog 段 id** | `userId/deviceId/fromSeq-toSeq` | 端上打包 | R2 路径 | 服务器只校验单调性 |

## 5. 各条流程详细设计

### 5.1 注册/登录流程(参考 Joplin Cloud + Bitwarden)

```
客户端"同步"设置页 → 输 email+密码
→ POST /auth/signup → 发确认邮件(Joplin 式:未点击前账号 inactive)
→ 点击链接激活 → 客户端登录 → 新设备邮件 OTP(Bitwarden 新设备验证层,2FA 之前的中间档)
→ session token(短期)+ refresh token(长期,可吊销)
```
- 密码:PBKDF2(WebCrypto,Workers/端上同构);不做手机号注册(合规重、单人不做)。
- 微信扫码登录:二期按需(国内转化利器,但要企业主体,与虎皮椒个人收款同阶段评估)。
- **忘记 E2E 密码 ≠ 忘记登录密码**:登录密码可重置(重置后旧密文按包裹密钥体系重包裹);E2E 数据密码(可选独立)忘记=不可恢复,注册页明示。

### 5.2 设备管理流程(参考 LS activate/deactivate + Obsidian)

```
添加:客户端展示 6 位配对码 / 或登录后一键添加本机
  → POST /devices {fingerprint, name, platform}
  → 服务器校验设备槽位 → 签发 deviceId + 签名权利文件(entitlement,14 天有效)
  → 客户端存权利文件,在线时静默续签;过期=同步暂停(本地功能不受影响)
解绑:账号面板设备列表自助"移除"→ 释放槽位(LS deactivate 模式)
超限:加购即时生效;降级先校验当前用量(Obsidian 降级守卫)
```

### 5.3 付费流程(两条通道,一个履约)

**海外(Lemon Squeezy,MoR)**:
```
设置页/官网 → LS Checkout(带 userId custom data)
→ order_created + license_key_created webhook(签名校验)
→ provision(user, plan):写 license 行、抬配额、发确认邮件
→ 用户在 app 内"我已购买"输入 license key → activate → 拿 instance_id
```

**国内(虎皮椒,个人可收)**:
```
官网/设置页 → 微信/支付宝扫码(虎皮椒聚合)
→ 支付回调【服务端验签后才发货——虎皮椒官方博客明示伪造回调盗发风险】
→ 同一个 provision() → 生成 PD- 激活码,页面即时展示+邮件备份
```
- 续费:海外 LS 订阅自动扣款(`subscription_payment_success/expired` webhook 续期/挂起);国内无代扣,**到期前 14 天 app 内提醒 + 续费链接,首年价终身锁定(思源机制,`price_locked_at` 字段)**。
- 宽限与挂起:到期 → 降免费档(数据保留 100 天,到期/30/60/90 四轮邮件,底稿 §2 唯一口径)→ 100 天后删除云端密文(Joplin Cloud 基准)。**任何一步都不碰本地数据。**
- 退款:海外 LS `order_refunded` → 吊销 license+禁新设备;国内=思源话术"激活前可退,激活后不退,买前可免费试用全功能 7 天"(试用=临时 license,过期自动收)。

### 5.4 后台管理(单人规模,克制)

自建后台 = 同一个 Worker 上加一条 IP 白名单的管理路由,**不做独立前端**(SQL/JSON 响应够用):
```
GET  /admin/user?email=      → 用户+设备+license+用量全景
POST /admin/user/:id/quota   → 手工调配额(客服场景)
DELETE /admin/device/:id     → 踢设备(用户手机丢了)
POST /admin/license/:key/disable → 停盗版/退款码
GET  /admin/metrics          → 注册数/激活数/付费数/存储总量(D1 聚合)
```
钱与退款在 LS/虎皮椒面板操作;指标看板从简(付费数、活跃设备、存储水位三个数)。**明确不做**:工单系统(邮箱+GitHub Issues)、多级权限(就你一个人)、CRM。

### 5.5 注销/数据擦除(参考 Joplin Cloud 隐私政策)

```
账号面板"删除账号"→ 确认邮件 → 立即停同步
→ 30 天后硬删:R2 密文对象先删,D1 PII 后删(90 天法律留存档案)
→ 隐私页一句话写明时间线;因数据是 E2EE,"删除"对我们成本极低=承诺可信
```

### 5.6 客服与反滥用

- 客服=邮箱+GitHub Issues,SLA 不承诺;FAQ 提前写:设备丢了怎么踢、换电脑怎么迁移、续费价锁说明。
- 反滥用三件套:激活端点限流(60/min)、fingerprint 重复检测、试用 license 全量走同一 provision(可一键批量吊销)。

## 6. 各流程的状态机(实现即按此写测试)

**license**: `issued → active →(expired→grace 14d)→ suspended →(renew→active | 90d→revoked)`
**device**: `pending → active →(解绑/超限)→ deactivated(可重新激活占新槽)`
**subscription(国内)**: `trial → paid(锁定价格)→ renewing → expired→grace → suspended`
**account**: `unverified → active →(注销请求)→ suspending → deleted(30d)`
每个状态迁移一个 webhook 或定时器触发,全部落审计表(D1 `audit_log`),出纠纷有据可查。

## 7. 与技术方案的接缝

- §4 的 ID 体系直接约束《同步整体方案》P2(ID 注入 deviceId 段)与 P3(设备注册端点)。
- entitlement 签名文件与 license 验签复用同一套 ed25519 逻辑(公钥内嵌 app,私钥离线)——**离线激活能力从第一天就有**,不依赖 LS API 可用性。
- P4 落地顺序:先做 provision()+license 行+设置页激活 UI(国内通道),LS 接入随后(海外审核有等待期)。

## 8. 决策出处速查

| 决策 | 抄的谁 |
|---|---|
| 限量不限设备 | Obsidian Sync(设备不限,限 vault/存储) |
| 试用替代退款+续费锁价 | 思源笔记 |
| webhook 履约+activation_limit+自助解绑 | Lemon Squeezy License API |
| 新设备邮件 OTP | Bitwarden new-device verification |
| 未激活邮件确认/100 天删除时间线 | Joplin Cloud |
| 国内收款验签后才发货 | 虎皮椒官方安全告示 |
| 后台=薄 CRUD,钱在支付面板 | Plausible/Ghost/Joplin Teams 通行做法 |
